# Control plane — building blocks

Use these directly only when no composite (SKILL.md, "Deterministic control plane") fits.

- Issue reads are scoped to the unit, from a per-process index with no disk cache: every open issue, plus the closed ones a unit reaches (sub-issues of an open or named parent, parents, numbers the command names). A missing closed issue is fetched by number.
- A short or empty GitHub page mid-list is refetched. One that stays short fails the command (exit 1); it never returns a truncated list.
- `git fetch origin` runs once per clone per process until something pushes or writes (`SDLC_FETCH_DEDUPE=off` disables it).

| Command | What it owns |
|---|---|
| `next-action <epic\|initiative> --run-id <id> --sync-epic [--repo-path <p>] [--skip-epic <n> ...]` | The one unit to work (Step 1); on an Initiative, the Epic to descend into (`references/initiatives.md`, "The Initiative loop"). `--repo-path` (default `.`) is where it reads dev-lane slot holders. `--sync-epic` first syncs `epic-<n>` with `main` (`epic_sync`) |
| `list-parallel-ready <epic> --repo-path <p> --run-id <id>` / `list-design-ready <epic> --repo-path <p> [--limit N]` / `list-ready-for-review <epic>` | Dev-lane / standing-epic design-lane / review pools |
| `lld-section --epic <n> --task <m> --repo-path <p>` | Only Task #`<m>`'s section of `epic-<n>/lld.md` |
| `doc-root <n>` | The unit's `docRoot` / `requirementsDir` |
| `worktree-add <n> [--unit epic\|initiative] [--base <ref>]` | The only way to make a worktree: resumes from `origin/<branch>`, else branches off the integration base. `diverged: true` → `references/parallelism.md`, "Working on a branch" |
| `review-worktree-add <n> --repo-path <p>` / `release-review-worktree <n>` | A reviewer's detached worktree at `origin/issue-<n>` / its removal (idempotent; `merge-pr` runs it too). Review agents run both themselves, never in the unit's dev worktree |
| `prune-stale --repo-path <p> [--dry-run]` | Closed units' worktrees (review and dev), landed branches on origin and locally, stale run-state files; then `worktree prune` + `fetch --prune`. Never touches open units or unmerged work |
| `claim <n> --role <r>` / `start-comment <n> --role <r>` / `sync-branch <n> [--unit epic\|initiative] [--base <ref>]` / `verify-exit <n> --expect-stage <s> [--pr <pr>]` | Steps inside `start-stage` / `transition` / `prepare-rework` / `skip-pr-review`. `verify-exit` also fails (`ok: false`, `head_check`) when the dev worktree is detached, on another branch, or differs from `origin/issue-<n>` |
| `route <n> --to product\|architecture\|development\|merge --reason "<one line>" [--from <stage just run>]` | Step inside `advance-standing` / `skip-pr-review`; refuses (exit 0) anything but a forward move on a standing child |
| `set-stage <n> --stage <s>` / `add-blocked-by <n> --on <dep>` / `create-issue --parent <n> --type <T> [--blocked-by <dep> ...] [--label L ...]` / `repair-issue <n> [--parent <p>] [--type <T>]` / `mark-todo <n>` | Stage a unit / order units (Epics: `references/initiatives.md`, "Cutting Epics from an approved Initiative") / the only issue-creation path / fill missing fields / set Pipeline Status `todo` on a new issue with none (CI path) |
| `open-design-pr <n>` / `merge-design-pr <pr> --issue <n> [--repo-path <p>]` | A phase-Task's design PR `issue-<n>` → `epic-<e>`. `transition` opens it; `skip-gate`/`waive-gate`/`finish-lld` merge it: re-run those, not `merge-design-pr`. Refusals (`behind_base`, `review_stale`, missing/`rework` review, `arch-review` below the skip bar) come back in `design_pr` / `failed_step` |
| `create-lld-tasks <epic> --repo-path <p>` / `merge-lld-doc <epic-n>` / `close-issue <n> [--repo-path <p>] [--not-planned --reason TEXT]` | Steps inside `finish-lld`. `mark-issue-closed` is CI's (`issues: closed`); the Bash guard denies it to every session. `create-lld-tasks` on a numbered doc adds only missing edges (`edges_added`); a section with `Placement: local — <reason>` gets `localLabel`. `close-issue` sets terminal fields then runs `cleanup` (`references/operations.md`, "Worktree release"); already closed → `already_closed: true`; `--not-planned`: `references/operations.md`, "Dropping a unit" |
| `place <epic\|initiative\|task> --where cloud\|local [--force] --repo-path <p>` | Hand an Epic or Initiative to a cloud or local session (`pipeline.placement.cloudLabel`), or keep one Task of a cloud Epic local (`localLabel`). Refuses (`refused`, `worktrees`) while local worktrees hold its units (a Task: while in progress or held), unless `--force` (`references/cloud-mode.md`) |
| `detach-epic <epic> [--reason TEXT]` / `reparent-issue <n> --parent <p> [--reason TEXT]` / `comment <n> --body TEXT\|--body-file <f>` | Take an Epic out of its Initiative (link + sibling edges) / move a plain issue (never an Epic) / a plain audit comment, no marker |
| `edit-issue <n> [--title T] [--body-file F] [--add-label L ...] [--remove-label L ...]` | Operator-directed title/body/label edit; refuses pipeline-owned labels and in-flight issues |
| `open-gate` / `check-gate` / `pass-gate [--doc-only]` / `skip-gate` / `waive-gate` | Gates (`references/gates.md`). On a phase-Task, pass/skip/waive merge its design PR and close it. `pass-gate --doc-only` closes a standing child or parentless issue whose merged gate doc is its whole deliverable, instead of claiming `development`; open its gate with `open-gate` even when the profile waives it |
| `approve-gate <n> --by-operator-session [--note TEXT]` / `request-gate-changes <n> --feedback TEXT\|--feedback-file <f>` | The operator's in-session gate decision (`references/gates.md`, "Deciding a gate in session") |
| `merge-gate <pr> --issue <n> --stage product\|architecture --operator-confirmed` | Merge an open gate PR **only when the operator explicitly told you to** (`references/gates.md`, "Merging a gate PR for the operator"); `pass-gate` finishes it |
| `record-cloud-session <epic> --session <url\|id> [--note TEXT]` / `cloud-heartbeat <epic> [--state working\|asking]` | Register a hand-started cloud session (`manual=1`) / stamp the live session's heartbeat; `start-stage` and `transition` do it in a cloud session, `asking` before an in-session question (`references/cloud-mode.md`, "Markers") |
| `record-operator-answer <n> --question TEXT --answer TEXT` | Record an in-session answer on the unit; `needs-human` returns to `todo` (`references/cloud-mode.md`, "Human channel") |
| `launch-cloud-epic <epic> [--relaunch] [--allow-overlap] --repo-path <p>` / `cloud-status <initiative\|epic>` / `nudge-cloud-epic <epic> [--force]` / `end-cloud-session <epic> --outcome closed\|waiting-human\|waiting-epic\|waiting-local\|stopped\|abandoned [--waits-on N ...] [--note TEXT]` | Place and start an Epic's cloud session (idempotent; `--allow-overlap` = operator's footprint override) / read-only cloud state (`relaunch_ready`) / continue a stalled session (`escalate` after two) / the session's end marker. A launch waits on an overlapping cloud Epic whose session ended or whose epic-PR merge is not on the launching base (`needs_base_sync`: `sync-branch <i> --unit initiative`, then launch). `pipeline.placement.softOverlapPaths` never collide (`references/cloud-mode.md`, "Initiative → cloud Epics") |
| `open-dev-pr [--allow-empty]` / `handoff-to-pr-review` / `record-pr-review` / `record-local-ci` / `record-design-review` / `post-comment <n> --role <r> --body-file <f>` | Stage-agent exit actions (their agent files own them). Brief `--allow-empty` when the design is verify-only. `open-dev-pr` adopts an open PR lacking its comment (`adopted: true`) and recovers a lost create (`recovered`). `handoff-to-pr-review`: `--summary` is the handoff comment (≤ 6,000); refuses `no_coverage_table` without its `### Acceptance criteria coverage` section, and `checks_failed` on a red non-infra check. `post-comment`: cap 2,000 chars (6,000 for a review role), a body identical to the role's last comment is `refused` (`duplicate_of`); allowed while parked by `pause-for-epic-regate`. `record-local-ci`: `references/operations.md`, "Local-CI attestation". `record-design-review` / `record-pr-review` report `escalation` (`recommend`: `replace` \| `needs-human`, `same_class_rounds`, `rework_since_last_clean`, `thresholds`); you decide (`references/rework.md`) |
| `update-pr-body <pr> --body-file <f>` | Replace an open PR's description (REST, cloud-safe; keeps `Closes #<n>`) |
| `pr-checks <pr>` / `rerun-checks <pr>` / `merge-pr <pr> --issue <n> [--run-id <id>]` | CI status / rerun the head's failed runs after an `infra_suspect` fix (`references/operations.md`, "A check the runner failed") / the only merge gate (refuses behind-base; reports `config_changed`; already merged → bookkeeping only, `recovered: true`; `cleanup` as `close-issue`). Both warn `uncovered_paths` (+ `uncovered_hint`) for files no `requiredWorkflows` entry covers. On `epic-<n>` → `initiative-<i>`, `pr-checks` skips `deferSuites` (`deferred_to_initiative`) |
| `mark-blocked <n> --dep <m>` / `mark-needs-human <n> --reason TEXT [--classifier-denied <step> --run-id <id>]` / `pause-for-epic-regate <n> --epic <e> [--gate-pr <pr>] [--found-by <stage>]` | Park a unit (first two release its worktree) |
| `park-finding --key K --text T\|--text-file F [--evidence URL]... [--target FILE]` / `supersede-park-issue <old> --by <new>` | Park a retro finding on `pipeline.retro.parkIssue` (`references/retro.md`) / retire a park issue |
| `pairing-counts <n>` / `show-config` / `show-issue-fields` | Valve counts + thresholds / effective tunables and running `plugin` version / the org's issue-field ids for `projectFields.issueFieldsRest` (laptop only) |
| `cite <path> --line N\|--lines A-B\|--match TEXT [--rev R] [--repo-path <p>]` / `verify-citations <doc> ...` | Emit a citation block from the real file / re-resolve every citation in docs (`all_resolved`) |
| `list-needs-human` / `check-epics-closeable` / `audit-issues [--epic <n>\|--initiative <n>]` | End-of-invocation sweeps; `audit-issues` also flags Epics with no phase-Tasks (`cut-phase-tasks` repair) |
| `resolve-thread --thread-id <id> [--reply TEXT]` | Reply to and resolve a gate PR thread; the gate-feedback agent runs it (`references/gates.md`) |
| `close-epic <n> [--no-carry-forward] [--clean-worktree]` / `record-epic-verification <n> --kind e2e\|exploratory --summary TEXT [--sha S] --repo-path <epic worktree>` / `provision-epic-stack <n> [--no-up]` / `teardown-epic-stack <n> [--project P] [--profile P]` | Epic close (`references/epics.md`, "Epic closing"). `--clean-worktree` discards untracked output first, refusing on tracked changes (`worktree_clean.tracked_changes`). Every result carries `base`; while verification is owed it syncs `initiative-<i>` with `main` (`initiative_sync`), fast-forwards the epic worktree (`epic_worktree`) and runs `pipeline.epicClose.prepare` (`prepare`). Already merged → bookkeeping only, `recovered: true`. Stack commands are no-ops unless `pipeline.stack.enabled` or a stack is named; teardown removes nothing while containers run |
| `check-initiative-closeable <n>` / `record-initiative-verification <n> --outcome met\|unmet --summary` / `close-initiative <n> [--repo-path <p>]` | `references/initiatives.md`, "Closing an Initiative" |
| `open-initiative-pr <i> --repo-path <p>` / `merge-initiative-pr <i> [--repo-path <p>]` / `initiative-profile <n>` | Initiative branch only: sync + open the PR `initiative-<i>` → `main` (idempotent) / its only merge gate (all Epics closed, current with `main`, checks green or attested, `closeSuites` attested; refusals exit 0 with `reason`, `evidence`) / the profile governing any unit (`references/epics.md`, "Initiative branch") |
| `mark-feedback-addressed <n>` | Step inside `finish-gate-feedback` (`references/gates.md`, "Addressing gate feedback"); never the agent's |
| `auto-pass-gate` / `mark-feedback-received` | CI-triggered only; never run them yourself |
